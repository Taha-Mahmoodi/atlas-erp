# DECISIONS.md — Design Decision Log

One line per consequential decision + rationale, so later sessions don't re-litigate or contradict earlier choices. Numbered, append-only; superseding a decision gets a new entry referencing the old one.

- **D-001 Bootstrap exception to "nothing directly on main":** the `.gitignore` root commit lands directly on `main` (GITHUB-WORKFLOW.md §1 explicitly orders it first); everything else reaches `main` only via `dev` promotions. Rationale: a branch cannot be cut from an empty repo.
- **D-002 Python toolchain = uv + Python 3.12:** uv manages the venv, lockfile (`uv.lock`, committed) and Python pin; CI uses `astral-sh/setup-uv`. Rationale: fastest reproducible installs, single tool for venv+lock+run.
- **D-003 Tests on SQLite (aiosqlite), runtime on PostgreSQL:** models are written PostgreSQL-first with SQLite-compatible type fallbacks (e.g. JSON variant for JSONB, Numeric for money); the full suite and CI run against in-memory/file SQLite, while docker-compose runs Postgres. Rationale: the prompt requires PostgreSQL-first + SQLite-compatible demo; SQLite keeps CI fast and dependency-free. DB-level financial constraints must be expressed portably (CHECK constraints, not Postgres-only features) or get Postgres-only guards documented per case.
- **D-004 Frontend package manager = npm:** lockfile committed; no pnpm/yarn. Rationale: zero extra tooling on contributor machines.
- **D-005 CI check names are stable from PR #1:** single workflow `ci.yml` with jobs `backend` and `frontend`; each job no-ops green while its directory doesn't exist yet. Rationale: branch protection requires named status checks; names must exist before the code does.
- **D-006 Makefile and docker-compose.yml are deferred to the first backend PR:** a Makefile whose targets point at directories that don't exist would violate the no-orphan-files rule in spirit. Rationale: every committed file must work the day it lands.
- **D-007 Tenancy via non-bypassable session filter:** a `do_orm_execute` hook adds `with_loader_criteria(TenantMixin, ...)` reading a `current_tenant_id` ContextVar to every ORM statement (lazy loads and bulk writes included), fail-closed when unset unless `system_context()` is active (exactly four call sites); `before_flush` stamps/validates tenant_id; composite `(tenant_id, id)` FKs + SQLite `PRAGMA foreign_keys=ON` are the DB backstop. Only mechanism with zero cooperation from query authors. Full spec: docs/architecture.md.
- **D-008 JWT access+refresh with CAS rotation and 10 s grace window:** HS256 with `ATLAS_JWT_SECRET`; 15-min stateless access token with `ver` checked against `core_users.token_version`; 14-day refresh JWT in an httpOnly cookie scoped to /api/v1/auth, rotated via compare-and-swap on hashed jti in `core_refresh_sessions` with reuse → family revocation, prev-jti accepted within 10 s so multi-tab races don't force logouts; argon2id (t=3, m=65536, p=4) off-thread. Full spec: docs/architecture.md.
- **D-009 RBAC as data + partial-bound WrapSerializer masking:** code-defined `core_permissions` catalog, tenant-scoped `core_roles` + join tables; `require_permission(key)` dependency resolves effective permissions in one join query, TTL-cached 60 s keyed on (tenant, user, token_version); field masking via `Masked(tp, permission)` WrapSerializer reading a `current_permissions` ContextVar, masked fields excluded from Update schemas. Tenants can't invent keys no code checks. Full spec: docs/architecture.md.
- **D-010 Split-phase audit capture in-transaction:** `before_flush` diffs updates/deletes from attribute history, `after_flush` captures inserts (generated PKs), `after_flush_postexec` writes one Core insert to append-only `core_audit_log` in the same transaction; per-dialect triggers (ATLAS_AUDIT_APPEND_ONLY) forbid update/delete; ORM bulk writes on audited models are hard errors. Audit is exactly as atomic as the change. Full spec: docs/architecture.md.
- **D-011 In-process event bus, collect-then-dispatch in-transaction:** `publish()` buffers in session.info; `run_in_uow()` drains FIFO before commit, handlers share the session (cap 50, cycle error), any handler failure rolls back everything — goods issue without COGS can never commit. `events.py` becomes a sanctioned declarative cross-module import (STRUCTURE §5 amendment); swap path is an outbox bus behind the same Protocol. Full spec: docs/architecture.md.
- **D-012 Document registry + flow links + gapless numbering (merged):** `core_documents` registry (nullable doc_no, partial unique index) with `DocumentMixin` NOT NULL document_id, `core_doc_links` edges traversed by one recursive CTE; numbers from `core_number_sequences` via atomic UPDATE...RETURNING, claimed only in the transaction that makes a document permanent (drafts numbered at posting) — so gaplessness falls out of ACID with no burned numbers. Full spec: docs/architecture.md.
- **D-013 Idempotency by PK reservation + atomic route capture:** `core_idempotency_keys` PK(tenant, endpoint, key); guard inserts 'in_progress' in a separate committed transaction (concurrent duplicates collide), replays stored responses on completed+matching hash; the handler's `idem.capture(schema)` stages the completed UPDATE on the business session so replay record and document commit atomically — fail-closed if capture is forgotten. Required on every financial/stock-document endpoint. Full spec: docs/architecture.md.
- **D-014 Keyset pagination + one error envelope + ATLAS_ token translation:** `{items, next_cursor, limit}` with base64url cursors fingerprinting sort+filters, expanded portable seek predicate, never OFFSET; all errors as `{error: {code, message, details, request_id}}` with dot-namespaced codes; a DBAPIError translator maps trigger tokens (ATLAS_PERIOD_CLOSED etc.) to envelope codes so DB backstops surface like service checks. Full spec: docs/architecture.md.
- **D-015 Exact money via TypeDecorators (supersedes D-003's "plain Numeric"):** MoneyType/QuantityType (PG NUMERIC(18,6), SQLite INTEGER micro-units ×10^6) and RateType (20,10 / ×10^10); Decimal-only in Python, strings in JSON; quantize ROUND_HALF_UP to currency decimals at posting; single largest-remainder `allocate()` in new `core/money.py` (STRUCTURE §2 amendment); triggers do comparisons and SUMs only. Plain Numeric float-round-trips on SQLite and breaks exact trigger sums. Full spec: docs/architecture.md.
- **D-016 Custom fields owned by core, not industry:** `core_custom_field_defs` registry + `validate_custom_fields()` + JSONB/JSON `custom_fields` column helper live in new `core/custom_fields.py` (STRUCTURE §2 amendment) — industry-module ownership would force upward imports from finance/inventory; templates and admin CRUD write defs through core services; flat scalar keys only, DECIMAL as strings, portable `.as_string()`-style JSON paths. Full spec: docs/architecture.md.
- **D-017 Universal journal: one-side CHECK, two-flush posting, reversal-only:** `fin_journal_entries` (nullable entry_number claimed at posting) + `fin_journal_lines` with all CO dimensions, transaction+functional amount pairs, `ck_fin_journal_lines_one_side`; balance trigger on DRAFT→POSTED (ATLAS_UNBALANCED_ENTRY), immutability triggers (ATLAS_POSTED_IMMUTABLE) allowing only the reversal status mutation; posting mutates loaded lines then header across two flushes; residual functional cent absorbed largest-remainder (no rounding line). Full spec: docs/architecture.md.
- **D-018 Period close enforced by per-dialect triggers + service check:** `fin_fiscal_periods`; `trg_fin_entries_period_open` re-derives the period from posting_date on DRAFT→POSTED (plus an INSERT twin) and aborts ATLAS_PERIOD_CLOSED when no OPEN period covers the date — catching wrong-period-id service bugs; service raises 422 'finance.period_closed' first; close refuses while drafts exist in the period. Triggers are the only cross-table guard on both engines. Full spec: docs/architecture.md.
- **D-019 FX: posting-time translation, realized at clearing, auto-reversing revaluation:** `fin_exchange_rates` (SPOT/CLOSING), `get_rate()` fails loud on missing rates; functional amounts frozen at posting (largest-remainder balancing); realized gain/loss posted inside the clearing entry via purpose-keyed `fin_posting_defaults`; `run_fx_revaluation` posts one FX_REVAL entry per (currency, account) and its next-period auto-reversal, validating up front that the next period is open. Full spec: docs/architecture.md.
- **D-020 Inventory costing: moving average + FIFO, same-transaction COGS, no negative stock:** `inv_item_valuations` updated under `with_for_update` (SQLite no-ops it; single-writer lock suffices, pg-marked tests prove the PG path); FIFO via `inv_cost_layers` + `inv_layer_consumptions` with exact reversal replay; the event bus posts the COGS journal entry in the SAME transaction as the move — stock and GL can never diverge; negative stock forbidden by service + CHECKs. Full spec: docs/architecture.md.
- **D-021 Statements are pure projections of `fin_journal_lines`:** five account types + cash_flow_category on `fin_accounts`; trial balance/P&L/balance sheet/indirect cash flow all derive from ONE aggregate over lines (denormalized is_posted/posting_date, no header join); retained earnings computed cumulatively on the fly; no stored totals anywhere; partial covering index `ix_fin_journal_lines_proj` keeps it sub-second to ~10M lines. Full spec: docs/architecture.md.
- **D-022 Single Alembic chain on both engines; migrations are the only schema source:** `create_all` banned even in tests (triggers live only in migrations); batch_alter_table everywhere + MetaData naming_convention; per-dialect trigger DDL side by side, re-executed after any batch-alter of a trigger-bearing table (SQLite copy-rebuild silently drops triggers); CI runs full suite on SQLite plus downgrade/upgrade and `-m pg` DB-guard subset on postgres:16. Full spec: docs/architecture.md.
- **D-023 Hand-written frontend types with a compile-time drift gate:** per-module `types.ts` mirrors Pydantic schemas (Decimal/date/UUID → string, enums → literal unions, Masked → `T | null`); committed `backend/openapi.json` (freshness pytest-asserted) feeds a gitignored openapi-typescript output checked by per-module `types.contract.ts` Equal-assertions in `npm run typecheck` — drift fails CI in both directions with zero runtime cost. Full spec: docs/architecture.md.
- **D-024 Frontend auth: memory-only access token + boot refresh + cross-tab single-flight:** access token never persisted; httpOnly refresh cookie drives a boot-time silent refresh; proactive renewal at exp−60 s, reactive single-flight retry on 401; `navigator.locks` + BroadcastChannel ensure exactly one tab rotates and the rest adopt the token — eliminating the multi-tab races the backend grace window only softens. Full spec: docs/architecture.md.
- **D-025 Tests on per-test template copies, not SAVEPOINTs:** a session-scoped fixture migrates ONE template DB (alembic upgrade head); each test gets a file copy (or PG `CREATE DATABASE ... TEMPLATE`) so real commits — idempotency reservations, run_in_uow, numbering — work as in production and triggers exist; factories provision through real services; raw-SQL DB-guard tests pin the ATLAS_ tokens on both engines; tenancy suite auto-covers new mappers. Full spec: docs/architecture.md.
- **D-026 Seed drives the real service layer, deterministically:** `seed.py` provisions five demo tenants from industry templates under system_context, then generates 3 months of interlinked P2P/O2C/production/FX flows through real services in `run_in_uow()` (RNG seeded per template+anchor); months 1-2 closed via the real close service; self-verifies trial balance, docflow chains, and inventory-GL reconciliation; `--reset` is the only sanctioned hard-delete, guarded by the `demo-` slug prefix. Seed doubles as a CI integration smoke gate. Full spec: docs/architecture.md.
- **D-027 Core platform tables and the auth router live in `core/`:** `User` (`core_users`) and `RefreshSession` (`core_refresh_sessions`) are defined in `core/models.py` and the login/refresh/logout/me endpoints in a new `core/security_router.py` (prefix `/api/v1/auth`). Rationale: auth/identity are cross-cutting platform concerns belonging to no business module (STRUCTURE §2 litmus — not a business concept), so they stay in `core/` rather than inventing a `modules/auth` package the module list doesn't sanction. `core/auth.py` stays ORM-free (crypto + JWT primitives only). Implements D-008. **Follow-on (PLAN 3.7, same precedent):** the document-flow read endpoint lives in a new `core/docflow_router.py` (`GET /api/v1/documents/{document_id}/chain`, guarded by `get_current_user`, tenant-scoped) — the document registry is platform infrastructure owned by no module, so its router joins `security_router.py` as a sanctioned core router wired in `create_app()`. Deviations from D-012's draft, all behaviour-preserving: route path is `/api/v1/documents/{id}/chain` (the binding PLAN-task path) not the draft's `/api/v1/core/documents/{id}/flow`; the D-012 numbering/docflow ORM models (`NumberSequence`, `Document`, `DocumentLink`) live in their concern files `core/numbering.py` / `core/docflow.py` (re-exported at the tail of `core/models.py` so they register on `Base.metadata`) rather than in `models.py`, to keep `models.py` under the ~350-line cap — STRUCTURE §2 lists both concern files and §8.5 ("filename promises content") favours co-locating each model with its claim/traversal logic. `core_number_sequences` keys on `(tenant_id, name)` with a `year_reset`/`current_year` pair (the binding task's column spec) rather than the draft's `(tenant_id, doc_type, year)` PK; semantics (gapless in-transaction claim, partial unique index, both-direction recursive CTE) are identical. `claim_number` uses the atomic `UPDATE ... RETURNING` path — verified working on the project's aiosqlite (3.53, >= 3.35), so the sanctioned SELECT-then-UPDATE fallback is unused; `WITH RECURSIVE` likewise verified on aiosqlite.
- **D-028 Idempotency + keyset pagination placement and behaviour (PLAN 3.8, implements D-013/D-014):** the `core_idempotency_keys` model + `reserve`/`IdempotencyContext`/`Idempotent` guard live in a new `core/idempotency.py`; the table uses the NATURAL composite PK `(tenant_id, endpoint, key)` exactly per D-013 (tenant_id overrides TenantMixin to join the PK, keeps `index=True` so the D-007 mapper-enumeration invariant holds). Migration `0007_idempotency`. Deviations, all behaviour-preserving except where noted: (1) the model is registered on `Base.metadata` from the BOTTOM of `core/db.py` (not the `core/models.py` trailing import that numbering/docflow use) because `core/idempotency` imports `core/db` for its session dependencies and `core/db` imports `core/audit`→`core/models`, so a trailing import in models would dead-lock the cycle. (2) The `Idempotent` guard reads `tenant_id` from the D-007 `current_tenant_id` ContextVar (set by `get_current_user`, which guarded routes declare first) rather than importing `CurrentUserDep`, to avoid the `deps`→`db`→`idempotency` import cycle. (3) `capture()` is called INSIDE the `run_in_uow` work so the completion UPDATE and the business document commit in one transaction (Atlas commits via `run_in_uow` inside the handler, not a deferred session-dependency commit). Consequent fail-closed deviation: on a business EXCEPTION the guard's teardown deletes the dangling IN_PROGRESS reservation and re-raises (handlers render the envelope) — fully fail-closed; on a FORGOTTEN `capture()` (handler returned 2xx) the teardown deletes the reservation and logs a server error but cannot convert the already-sent 2xx to a 500, because the `run_in_uow` commit precedes teardown — a documented relaxation of D-013's literal "teardown rolls back" (which assumed a deferred commit). Replay short-circuit: `reserve` raises `IdempotencyReplay` (an AtlasError subtype) whose handler in `app.main` re-emits the stored status+body with `Idempotency-Replayed: true`, so a completed-key replay never runs the handler body. **Keyset pagination** lives in a NEW flat core file `core/pagination.py` (`paginate`, `OrderKey`/`SortDirection`, base64url cursor codec with sort+filter fingerprint, `CursorParams`/`cursor_params` with limit cap default 50 / max 200) — STRUCTURE §2 amendment, same precedent as `core/money.py`/`core/custom_fields.py`; this DEVIATES from D-014's letter (which puts `paginate` in `core/db.py` and the codec in `core/schemas.py`) because the keyset machinery is substantial and cross-cutting (§8.5 one-concept-per-file). The `Page` envelope stays in `core/schemas.py`. The seek predicate is written in the EXPANDED portable OR-form unconditionally (verified: this project's aiosqlite 3.53 DOES support uniform-direction row-value tuples, but not MIXED-direction, and Atlas lists mix ASC/DESC, so the expansion is the only universally-correct form on both engines per D-014). Full spec: docs/architecture.md D-013/D-014.
- **D-029 AP/AR sub-ledger is keyed by an opaque `partner_id`, not a finance-owned partner master:** finance is the bottom dependency (everyone may read `finance/queries`; finance imports no module), but the vendor master lives in procurement (PLAN 6) and the customer master in sales (PLAN 7) — both *above* finance. So finance AP/AR open items, payments, dunning and aging are keyed by an opaque `partner_id: UUID` plus a denormalized `partner_name` carried on each document; finance never FK-references a partner table. The vendor/customer masters own the identity (their PK *is* the partner_id) and call finance services to create bills/invoices and run payments. This honors the parity doc's "separate vendor and customer masters, no unified Business Partner" while keeping the dependency direction legal. Realized FX is computed at clearing here (D-019). Trade-off vs a finance-owned `BusinessPartner`: no referential FK from open items to the master (the owning module guarantees the id), accepted for the clean layering.
- **D-030 AP (PLAN 4.5) placement + the journal `skip_translation` clearing hook (implements D-029/D-019):** the four AP tables live in `finance/models/payables.py` (re-exported from `models/__init__`); AP request/response schemas live in a NEW sibling `finance/payables_schemas.py` and the AP endpoints in a NEW sibling `finance/ap_router.py` — both siblings (not a `schemas/`/`router/` package) exactly mirror the sanctioned `fx_router.py`/`tax_router.py` precedent, because `schemas.py`/`router.py` are at the STRUCTURE §3 400-line cap and the AP surface is self-contained; `ap_router` mounts into the finance router via the same `include_router` one-surface pattern (no second mount in main.py). The AP service is split across `service/vendor_bills.py` (draft + post), `service/payment_clearing.py` (open-item validation + realized-FX line construction), `service/vendor_payments.py` (payment document + run), and `service/ap_aging.py` (the projection) to keep every file under the cap. **Realized FX at clearing (D-019):** computed per cleared bill as `functional-at-bill-rate − functional-at-payment-rate` over the cleared transaction amount (the bill's frozen rate is read from its posted AP-control journal line, not re-looked-up), posted to the `fx_realized_gain`/`fx_realized_loss` posting-default account inside the SAME payment entry. This required a behaviour-preserving extension to `service/journal.post_entry`: a new keyword `skip_translation: bool = False` — when the caller has already set explicit per-line functional amounts (the only case where functional ≠ transaction × a single entry rate), the engine validates those balance instead of re-translating. The realized-FX line is denominated in the functional currency and carries a positive transaction amount equal to its functional amount, so the per-line one-side CHECK (D-017, on transaction amounts) holds while the balance trigger (functional sums only) balances — no zero/zero line. Open items are partner-keyed by the opaque `partner_id` stamped on the AP control line (D-029); finance imports no module above it (verified). AP documents register in `core_documents` and link bill→journal (`posts`) and payment→bills (`pays`) so the document-flow chain spans the AP flow. Migration `0012_finance_ap` creates four tables and alters nothing (no trigger-bearing table touched, D-022); autogenerate confirms zero model drift on SQLite.
